## [Unreleased]

### Breaking

- `identity`: the first-run setup over HTTP is closed by default. New config `identity.setup`: `offline` (the default) or `http`. Under `offline`, `POST /api/setup` is always refused, 403 `setup_offline`, with a message naming `<app> identity setup`; before, the first caller to reach an empty instance became its owner (an agent on the same host did exactly that through the loopback setup). `GET /api/setup` still answers, now also with `setup_over_http`. Why a default and not an opt-in: loopback is not a boundary, and a service started before its bootstrap must not be claimable. An app, a test or a script that relied on `POST /api/setup` either creates the owner offline (below) or opts back in with `identity: {setup: http}` in its manifest config or `SUBSTRATE_CONFIG`, for local development only. Under `http` nothing changes (`setup_closed` 409 once an owner exists). (migration: none; set `identity.setup: http` where the HTTP first-run is still wanted, otherwise run `<app> identity setup` before the first start)
- The `sqlite` module is now `database`, on libs `core/store` with a `driver` of `sqlite` (default) or `postgres`. Config moves from `sqlite.*` to `database.sqlite.*`; `sqlite.UseMigrations` and `sqlite.From` become `database.UseMigrations` and `database.From`. Postgres connection strings are secrets: `dsn_file`/`dsn_env` (and `migrate_dsn_*`), never written in config. (migration: none; pre-release, no consumers)

### Added

- `identity`: offline account recovery. `<app> identity recover --user <name> [--url URL] [--ttl 30m]` mints a
  single-use, short-lived link (`<url>/recover#r=…`, at most 24h, only its hash stored). Opening it signs that
  user in and lets them set a new password and clear their passkeys (passkey-only off) and TOTP. Their other
  sessions end. Routes: `POST /api/recover/check` and `POST /api/recover`, both public, with this app's origin
  and `X-Requested-With`, and rate-limited. Minting and use are logged. Go: `Service.RecoveryLink`,
  `RecoverURL`. Migration `0006`.
- `identity`: a passkey sign-in with a passkey the app doesn't have (removed, or another install's) answers 401
  `passkey_unknown` with a plain message instead of `invalid_login`.
- `identity`: TOTP, a second sign-in step (RFC 6238: SHA-1, 30 seconds, 6 digits). Enroll with `POST /api/identity/totp/begin` (`{secret, uri, qr_svg}`) and `POST /api/identity/totp/confirm` `{code}`, which answers ten recovery codes once (stored only as hashes). `POST /api/login` then answers 401 `totp_required` until `code` is sent; a recovery code also works, once. Each code step is used only once. Also: `GET /api/identity/totp`, `POST /api/identity/totp/recovery-codes` and `DELETE /api/identity/totp`, both of which take a code, and the admin reset `PUT /api/identity/users/{id}` `{reset_totp: true}` (the users listing marks `totp`). `identity.require_second_factor` (roles) keeps such accounts' sessions scopeless until they have TOTP or a passkey. The profile adds `totp` and `second_factor_required`, and `sign_in` can be `password+totp` or `password+recovery`. A passkey sign-in needs no code. Migration `0005`. New dependency `rsc.io/qr` draws the QR code.
- `identity`: invites. An administrator makes a single-use, expiring invite for a role (`POST /api/identity/invites` `{role, label?, ttl_hours?}`, default 7 days, at most 30; the code is returned once and stored only as a hash), lists the pending ones (`GET`) and revokes one (`DELETE /api/identity/invites/{id}`); nobody invites to a role whose scopes they lack. The invited person's page checks the code (`POST /api/invite/check`, public, rate-limited) and accepts it (`POST /api/invite/accept` `{code, username, display_name, password}`, public, with `X-Requested-With` and this app's `Origin`), which creates the account with the invite's role and signs them in, atomically with spending the invite. Go: `Service.CreateInvite`, `PendingInvites`, `RevokeInvite`. Migration `0004`.

- `identity`: passkeys (WebAuthn, go-webauthn). On when `identity.public_url` is a secure context (https, or http on `localhost`; `passkeys: false` turns them off): the relying party is that URL's host and its origin the only one accepted. People add passkeys to their account (`POST /api/identity/passkeys/register/{begin,finish}`, resident keys required), list, rename and delete them (`GET|PUT|DELETE /api/identity/passkeys…`), and sign in without a username (`POST /api/passkey/{begin,finish}`, rate-limited per address); each ceremony's server half is stored, single use, for 5 minutes. `PUT /api/identity/passkey-only` makes an account refuse its password (403 `passkey_required` after a correct password), which needs a passkey, and its last passkey cannot then be deleted. Sessions record how they were signed in (`password`, `passkey`, `setup`), reported as the profile's `sign_in`; `GET /api/setup` adds `passkeys`. Migration `0003`.
- `identity.public_url`: where people reach the app. Its origin is accepted like the request's own, an https one makes the session cookie `Secure`, and its host is the passkey relying party. Behind a TLS proxy, the proxy's public address.
- `identity.trusted_proxies` (CIDRs) and `forwarded.HTTPSFrom` / `forwarded.ParsePrefixes`: a TLS-terminating proxy's single `X-Forwarded-Proto: https` is believed from those peers only (cookies `Secure`); `trusted_proxy: true` remains the loopback case (`forwarded.Loopback`).

- `identity`: spaces, memberships and roles. One space (`default`) for now; every user has a role in it (`owner`, `admin`, `member`, `guest`) that grants scopes on top of the user's own (`owner` → `*`; `admin` → `<app>.admin`, `<app>.use`, `<app>.read`; `member` → `<app>.use`, `<app>.read`; `guest` → `<app>.read`), so the guard keeps checking scopes. `POST /api/identity/users` and `PUT /api/identity/users/{id}` take `role` (a new user is a `member` when neither role nor scopes are given; nobody grants a role whose scopes they lack; the last owner keeps the role, 409 `last_owner`); users, the profile and sign-in answer with `role`, and the profile's `scopes` are the effective ones. Go: `Service.Role`, `Service.SetRole`, `PublicUser.Role`, `RoleScopes`. Additive: existing users get a role from their scopes on upgrade (`*` owner, `<app>.admin` admin, else member).
- `identity`: setup links. `<app> identity setup-link [--url URL] [--ttl 30m]` (Go: `Service.SetupLink`, `SetupURL`) mints a single-use, expiring setup token and prints `<url>/setup#t=<token>`; `POST /api/setup` with `setup_token` (plus `X-Requested-With` and this app's `Origin`, rate-limited per address) creates the owner and signs them in under either `identity.setup` setting. Only the token's hash is stored. `GET /api/setup` also answers `setup_link: true`. The open form stays closed under `offline`: the token is the authority, and only someone who can run the binary against the data gets one.
- `identity`: numbered migrations. The `identity_*` tables are created by goose migrations (`modules/identity/migrations/{sqlite,postgres}`, libs `core/store/migrate`) under their own version table, `identity_schema`; `identity.Migrations` is the source. `0001` is the previous schema (`CREATE TABLE IF NOT EXISTS`), so a database made by an older release upgrades in place.

- `substrate pins check --app DIR --frontend [--frontend-dir frontend] [--no-npm-ls] [--bom FILE]`: holds an app's frontend to the BOM kits. Reads `package.json` and `package-lock.json` (v2/v3) and fails on a top-level kit that is not the exact BOM version (in either file), a range on a pinned kit that the resolved copy does not meet or that has no copy (npm's invalid and missing), a pinned kit installed again, nested, at another version (every path listed; `kit_exceptions` honoured and printed as accepted), and anything `npm ls --all --package-lock-only` reports for a pinned kit. Why: Parallax's lockfile kept stale nested 0.4.0 design-tokens and design-components copies that made `npm ls` fail while `pins check --npm` (registry metadata only) passed. The lockfile analysis needs no network and no `node_modules`; `npm ls` needs npm and the check fails without it unless `--no-npm-ls`. `--bom` takes a `bom.yaml` in place of the one the app's Substrate release carries. Read-only: it changes no app. Nothing changes for existing flags.
- Shared `agents.dir` config (default `agents/` beside app config) and the `agents` path helper: absolute authored paths, sorted agent subdirectory names, and separate per-agent state paths under the host’s state root. No Nanite dependency. See `docs/agents.md`.

- `genui/gateway` and optional `genui` module: reviewed-pattern surfaces and
  scoped action/recovery routes backed by host-owned persistence, policy and
  execution ports. Durable claims survive uncertain results and restart;
  recovery preserves the selected choice and complete form input without
  confirmation secrets. No default authority, listener or production store is
  installed. Frontend generation uses the published package pinned in the BOM.

- `httphost.ServeOptions.Listener` (CW-20261115-0003): serve a `net.Listener` the app created (a unix socket, a socket-activated descriptor) instead of listening on `Addr`. Serve keeps `Stopping`, handler tracking and the graceful drain over it, runs the auth bind check on `Listener.Addr()` (a unix address as `unix:<path>`) and closes it on every return, a refused bind included. In `off` and `permissive` a unix listener must be a socket file that other users cannot write to: an abstract socket (`@name`) or an `o+w` socket file is refused (file permissions are its only protection). `httphost.ListenUnix(path, perm)` creates one safely: bound in a private directory next to `path`, chmodded there and linked into place, so the socket is never reachable with the umask's permissions; a stale socket is replaced only if nothing answers on it; it is removed on close. `httphost.ServeOptions.ConnContext` (CW-20261115-0004) is passed to `http.Server.ConnContext` after Serve's own and receives the connection exactly as `Accept` returned it, never wrapped, so a `*net.UnixConn` assertion holds. `httphost.PeerCredentials(r)` returns the uid, gid and pid of a unix-socket peer (Linux `SO_PEERCRED`, darwin `LOCAL_PEERCRED`/`LOCAL_PEERPID`; `ok` is false on TCP, on a wrapped conn, in httptest and on other platforms). A `unix:` address in `ServeOptions.Addr` or config `httphost.addr` without a `Listener` is refused with an error naming `ServeOptions.Listener` (it failed before with a TCP lookup error). `golang.org/x/sys` becomes a direct, pinned dependency (same version). Additive; nothing changes for callers that set none of these.

### Fixed

- `identity`: `PUT /api/identity/users/{id}` with `"scopes": []` gave the user every scope the caller held (an owner's `*`) instead of clearing them; an empty list now clears. A cookie-authenticated connection upgrade (a WebSocket handshake, a `GET`) now needs this app's `Origin`, like a cookie-authenticated write: before, a page on another site could open a socket with the session cookie.

- `database`: `UseMigrations` with an empty `migrate.Source` (a cleared registration, as tests do in cleanup) no longer panics in goose at the next `Start`; it now means "no migrations", as the package comment says.
- `pluginhost`: follow-ups to the per-Spec routes (CW-20261115-0107). `Start` now refuses a plugin id that is not one plain path segment (letters, digits, `_`, `.`, `-`, starting with a letter or digit) with an error naming the id, before any plugin spawns; before, `a b` made `httphost.Handler` panic, `{x}` registered a wildcard that claimed all of `/api/plugins/` again, and `a/b` or `..` gave dead routes. `UI()` reports the list `Start` mounted, not a later `UseSpecs`. Tests now pin the guard over app routes under `/api/plugins/` in enforce mode (401, 403 `scope_required`, 403 `route_not_mapped`), an id no plugin registered, and a finer scope kept to its own plugin; the forwarded request asserts 502.
- `httphost`: a request whose path a method-specific mount, module route or `/healthz` serves, but whose method none of them accepts (`POST` to `GET /.well-known/jwks.json`), is answered 405 `method_not_allowed` in the flat body with an `Allow` header; before, it fell to the SPA and got 200 HTML, which a client checking only the status took for success. `GET` and `HEAD` to such a path still reach the SPA (a client route may share a path with a `POST` endpoint), and an unknown path still loads the SPA as before. (CW-20261115-0006)
- `mcp`: stdio under `StdioOptions.LocalTrust` now applies the mcp endpoint scope gate in enforce mode, as a token and `/mcp` over HTTP already did. `ServeStdio` refuses to start, naming the scope, when `LocalScopes` does not cover `mcp.scope` (the scope itself, `<app>.*` or `*`); before, a local principal without it reached every tool that had no per-tool scope. Default `LocalScopes` (`*`) and permissive/off modes are unchanged. An app that narrows `LocalScopes` must list the mcp scope (Cerberus already does). (CW-20261115-0043, part b)

- `config`: follow-ups to the numeric override conversion. A nested map with a non-string key (`{1: a}`) in the override file is now refused with an error naming the key path (it used to pass through unconverted). The doc comment no longer claims big integers are "never rounded": a YAML integer beyond 64 bits is decoded by yaml.v3 as a float64 and cannot be told from a float, so it arrives rounded; only 64-bit integers above 2^53 are refused. The queue override tests no longer hang on failure (the release cleanup now runs before the queue stops) and the `poll_ms` test now fails when the conversion is removed (the queue starts empty so the worker sleeps a poll interval first). Removed dead `int` cases in `database` (`sqlite.read_pool`) and `events` (`retention_records`): every number arrives as `float64`.

### Fixed

- `config`: a bare integer in the `SUBSTRATE_CONFIG` override file was ignored, or refused with a wrong message, by every module that reads a number. YAML decoded a whole number to `int`, the manifest's generated JSON gives `float64`, and modules read numbers with `.(float64)`, so the module fell back to its default (`database.postgres.max_conns`, `auth.denylist_interval_seconds`, `identity.min_password` and `bcrypt_cost`, `scheduler.tick_ms`, `due_batch` and `claim_lease_seconds`, `queue.poll_ms`, `concurrency` and `max_tries`) or refused start with "must be a number" (`queue.retry_after_secs`). The merge now converts every integer from the override file to `float64`, at any depth and inside lists; non-integer floats, booleans and strings are untouched; an integer above 2^53 is refused with an error naming the key rather than rounded. The live override files the driver checked (Mentat, Loom, Parallax, Basalisk) set no bare integer, so nothing live changes. `docs/writing-a-module.md` no longer says override numbers arrive as `int`.
- `database`: two processes starting at the same moment on one new SQLite file no longer fail with `database is locked` at open or `table ... already exists` at migrate. On SQLite (file paths only) open and migrate now run under an exclusive `flock` on `<path>.open.lock`; the kernel releases it when the holder exits, so there is no stale-lock case. New config `database.sqlite.open_lock_timeout` (Go duration, default `30s`, must be positive); a longer wait fails the start with an error naming the lock file. Not taken for `:memory:` or Postgres; a no-op on non-unix builds. A new file `<db>.open.lock` appears beside the database. Documented in the store contract (`docs/adopting-substrate.md` section 4).
- `identity`: two processes starting at once on one new data directory now end with the same signing key. The first-start create was a plain write, so each process could keep its own key while the file held the last writer's; it is now an exclusive create (private temp file hard-linked to `key_file`) and the loser reads the winner's key. The JWKS and retired-set scratch files are named per process, so concurrent starts no longer collide on them.

### Added

- `httphost.Harden(app, h, HardenOptions) (http.Handler, error)`: the request hardening chain for `httphost.Handler`'s result or an app's own handler (Tether's closed remote listener and socket handler). Supersedes #23. Outermost first: an access log (`AccessLog`; method, path through `redact.Text`, query parameter names only and never values, status, bytes, duration, remote; no header is logged, so `Authorization` and cookies never are; it changes no request), panic recovery through libs `core/panics/httpguard` (500 `internal` with a ref instead of a dropped connection; the panic is reported to `Logger` redacted), forwarding headers (`Forwarded`, `X-Forwarded-For`, `X-Forwarded-Host`, `X-Real-IP` removed; `X-Forwarded-Proto` kept and believed by the new `httphost.Scheme(r)` only under `identity.trusted_proxy`, as exactly one value from a loopback peer (package `forwarded`), otherwise removed), a Host check (`CheckHost`/`AllowedHosts`: loopback plus names served to any peer, what #23 called `direct_hosts`; 403 `host_not_allowed`; never applied to a request accepted on a unix-socket listener, decided from the connection; a bad entry such as `*`, a scheme, a path or user info is an error naming `httphost.allowed_hosts`), an Origin check on writes (`CheckOrigin`/`AllowedOrigins`: own host plus the list, 403 `origin_not_allowed`) and a body limit (`MaxBodyBytes`; 413 `body_too_large` for a declared oversize body, a read error past it; default 8 MiB when Harden is used in code, none when only config turned it on unless `max_body_bytes` is set; negative is none). `ErrorBody` writes the refusals and the 500 in another envelope for a raw handler. - `database` named stores. An app can keep boot-critical data in its default (local) store and growing data in a second store, usually Postgres, that may be down without taking the app down. No port needs this for its Substrate cutover; it is for the later Postgres switch. Config: `database.stores.<name>` takes the same block as `database` plus `required` (default true), `connect_timeout`, `retry.initial`/`retry.max` and `ping_interval`; a named store must say its `driver` (and a SQLite one its `sqlite.path`), unknown keys are an error naming the store and the key, and no two SQLite stores may be the same file. `database.start_wait` (default 3s, `0s` to not wait) bounds how long `Start` waits for the optional stores' first attempts together. API: `database.Named(app, name)` returns a `*Handle` with `Get()` (the store, or an error wrapping `database.ErrUnavailable`; it never waits on the network), `Ready()`, `Status()` (state, redacted target `host:port/db`, redacted last error, attempts, since), `Wait(ctx)` (returns an error once the module is stopped), `OnChange(fn)` and `Report(err)`; also `database.Statuses(app)`, `database.IsUnavailable(err)`, `UseNamedMigrations`/`UseNamedMigrationFS(name, ...)`, `database.MigrateNamed(ctx, app, name)` for a deploy step, `database.Gate(h)` and `database.GateWith(h, deny)` middleware and `database.WriteUnavailable` (503 `database_unavailable` with `Retry-After`). `Handle` methods are safe on a nil handle, but `Gate` and `GateWith` panic at construction on one (a misspelt store name should not become a route that is quietly always 503). The cli module gets `<app> db migrate --store <name>` when the app has named stores, for the deploy step. Each named store keeps its own goose version table, `goose_db_version_<name>`, unless the source sets `Table`; otherwise two stores in one database would share one table and the second store's migrations would be skipped. A required store (the default, and any named store unless `required: false`) fails `Start` when it cannot be opened and makes `/healthz` 503 if it goes down later. A store with `required: false` never fails `Start` for an outage: the app comes up, `/healthz` reports `degraded` with HTTP 200 and a `database.<name>` check naming the store and target (the process is serving, and a 503 would make a deploy gate roll the app back or a supervisor restart it), `Get` is refused, and a background loop reconnects with exponential backoff (about 1s doubling to 30s, 20% jitter), re-reading the secret each attempt; when the server returns the store is ready again with no restart. States: `unavailable` (cannot be reached, retried) and `failed` (a rejected login, a missing database, a schema that is behind or a failed migration, a configuration problem found after start; retried at the slowest backoff, logged at error level). State changes are logged with the store name and target. No spooling, no queue: a refused write is refused. Credentials never reach health, status, logs or errors (URL and key=value DSNs, quoted values, `sslpassword`, userinfo). A misconfiguration fails `Start` (wrong types and values included, each error naming `stores.<name>`); a missing secret file or an unset or empty variable counts as an outage, while a secret file that cannot be read (permission, a directory, empty) fails `Start` and names the path. `migrate_dsn_*` is read only when the process migrates (`schema_mode: auto`, or `db migrate`), so verify mode never needs the schema owner's secret. Credentials are masked through libs `security/redact` and the target comes from `pgconn.ParseConfig` (`github.com/jackc/pgx/v5` is now a pinned third-party dependency). - `queue` and `scheduler` take `autostart: false` and expose `queue.Run(app)` and `scheduler.Run(app)`. An app whose one binary is both a CLI and a daemon sets it, and only its `serve` command starts the worker and the engine, so a short-lived command (`version`, `health`, `mcp`) never runs jobs or fires schedules.
- `httphost.Serve`: the one standard way to listen. Address from config `httphost.addr` (default `127.0.0.1:8080`), bind validated against the auth mode (off and permissive refuse a public address), header and idle timeouts, no write timeout so SSE is not cut off, and graceful shutdown when the context ends so in-flight requests finish. The examples use it; no app writes its own listener code, and no `ADDR` environment variable.
- Fixed: a `SUBSTRATE_CONFIG` override with a manifest that has no `config:` block panicked (the generated config text is `null`, which decoded to a nil map). `boot.Start` now always has a map.
- `httphost.Options.Mounts`: app handlers outside `/api/` for paths a protocol fixes (an A2A endpoint, `/.well-known/...`). Guarded by the auth module and given the flat error body unless `Open` is set for public discovery; a pattern that would shadow `/api/`, `/healthz`, `/mcp` or the SPA, or conflict with another, is an error.
- `mcp.ServeStdio`: the same MCP server and tools over stdio, for an agent that launches the app as a subprocess. The caller is identified once from a token file (`mcp.stdio_token_file` or `StdioOptions.TokenFile`), verified by the auth module, and stamped on every tool call, so per-tool scopes behave exactly as over HTTP; enforce mode requires a token holding the `/mcp` scope, and the token and its path never appear in errors. `auth` publishes its verifier (`auth.verifier`, `auth.Verify`) for this.
- `queue` module over libs `core/util/queue`: handlers registered with `queue.Handle`, a worker started and stopped with the app, durable SQLite driver on the database module (or `memory`, or `queue.UseDriver`, which Postgres needs because libs ships no Postgres driver), retries up to `max_tries`, then the failed store.
- `scheduler` module over libs `core/util/scheduler`: durable schedules (cron, interval, one-time) with leased claims, retries and overlap policy, on libs' reference SQLite store (or `scheduler.UseStore`). A fired job is pushed to the `queue` module by default, so scheduler, queue and handler compose without glue; `scheduler.UseRunner` replaces the dispatch.
- `router` module over libs `core/util/router`: a rule set from `rules_file` or `router.UseRules`, compiled at start; `router.Route` returns a ledger-shaped decision with a real confidence gate. Policy, escalation and snapshot hooks go in `router.UseConfig`.
- CI runs a Postgres service (`ci.postgres_image` in the BOM) so the database module's Postgres path is tested for real.

- UI contribution manifest (`ui/`, v0): a module that implements `module.UIContributor` returns an embedded `ui.json` (contributions, envelopes, routes), validated against the design team's approved vocabulary v0.3 (`nav.item`, `nav.group`, `settings.region`, `surface`, `panel`, `dock.tab`, `widget`, `slot`). `settings.region` references admin-manifest groups and never defines them; frontend routes may not equal a backend path; the generated manifest checks nav groups, slot targets and route clashes across modules. Package versions are never written there; `package.version_ref` points into the BOM.
- Declared routes: `module.AddRoutes` binds each route in `ui.json` to a handler and a scope (`{app}`, `authenticated`, or the module's `scope` config), and httphost mounts and scope-maps them, so a route cannot be left unmapped. Paths outside `/api/` (such as `/admin/...`) are mounted exactly under the same guard. `capabilities` now uses it.
- `GET /api/me` (auth): the caller's principal and the guard mode, for any verified caller.
- `apierr`: one flat error body `{code, message, details?}` for everything Substrate serves; httphost rewrites the auth guard's nested body to it, because the app-runtime client reads `message` at the top level.
- `events` module: replayable SSE at `GET /api/events?topic=` over libs `streamhub` and `ssekit`, with Last-Event-ID resume, an explicit `gap` frame, heartbeats, a per-app topic authorizer and `events.UseLog` for a durable log. Scope `<app>.events`.
- BOM `kits:` pins the npm packages the frontend may name (public registry, `@hollis-labs`, exact versions). `substrate pins check --npm` verifies each is published (nightly).
- `substrate frontend -f substrate.yaml [-o dir]` writes `frontend.manifest.json`: the merged contributions of exactly the modules the manifest selects (nav with group checks, settings, routes) and the BOM-pinned kits, with the base design kits added when anything contributes UI. Removing a module removes its UI. Envelope TS types and the binding-table input follow the S0 consolidation.
- `pluginhost` routes are declared in `ui.json` (any method, subtree `/api/plugins/`) with scope `<app>.plugins`; an app maps finer per-plugin scopes on the scope table and those win. `pluginhost.RoutesKey` is removed. Declared routes may now use method `*` and subtree paths.
- `substrate upgrade [-dir] [-to] [-dry-run] [-allow-unmigrated]` (`upgrade/`): reports the BOM pin changes and changelog between two releases, applies registered mechanical migrations, moves the one Substrate requirement, validates the manifest with the target release's CLI, builds, and restores `go.mod`, `go.sum` and migrated files on any failure. Refuses downgrades, local `replace`, unmigrated breaking changes and unreleased targets without `-allow-unmigrated`. `docs/compat-policy.md` defines what is covered, what breaks, and the `### Breaking` / `(migration: id|none)` changelog convention.
- App-level bump test (`e2e/`): an app that requires Substrate only resolves every BOM pin exactly, at v0.1.0 and at this tree. An end-to-end upgrade test moves a real app from v0.1.0 to the proxy's main.
- `docs/writing-a-module.md`.
- Conformance: every contribution validates, and every declared route is mapped and served in enforce mode.
